# ES-40 + ESX-8CV: two units, sixteen CV outputs

Studio supports the ES-40's encoded S/PDIF transport, with one ESX-8CV per configured
unit. This is separate from the direct DC audio used by an ES-3. Each expander
receives eight 12-bit CVs in factory-calibrated mode (384 DAC counts per volt,
roughly ±5.33 V). All eight outputs update once per 24 audio samples: 2 kHz at
48 kHz. Updates within a cycle are staggered, so pitch and gate are not physically
simultaneous. Studio latches all eight CVs at each cycle boundary so a note change
cannot open a later-numbered gate with the previous cycle’s pitch. Put pitch
before its gate in the jack map; measure the receiving
voice's response before relying on very short triggers.

The implementation matches the manufacturer's [8CV and ES-40 Rack encoders](https://github.com/expertsleepersltd/vcvrack-encoders/tree/95496e8a955407889bbab94cf404cf356802bb76/src).
It uses signed integer PCM with the encoded 24 bits at the top of each sample,
with PortAudio clipping and dithering disabled. This avoids float-conversion
category selection in HydraPy. It **does not** prove that PipeWire, JACK, ALSA,
the interface mixer, or the physical digital link preserves those bits.

## Configure both units

Install `hydrapy[cv]` and use `hydrapy devices` to identify the audio devices and
output channel counts. Save a JSON profile like the following, replacing both
device names, the **zero-based** S/PDIF channel pairs, and the physical ES-40
header numbers. These channel numbers are examples, not detected Digi003 or
Scarlett assignments. ESX-8CV jack numbers and ES-40 headers are **one-based**.

```json
{
  "format": "hydrapy-cv-1",
  "devices": [
    {
      "device": "REPLACE with first interface name",
      "samplerate": 48000,
      "es40": [{
        "name": "ES-40 A",
        "channels": [8, 9],
        "header": 1,
        "map": {"1": "pitch1", "2": "gate1", "3": "pitch2", "4": "gate2",
                "5": "clock", "6": "reset", "7": "vel1", "8": "z"}
      }]
    },
    {
      "device": "REPLACE with second interface name",
      "samplerate": 48000,
      "es40": [{
        "name": "ES-40 B",
        "channels": [8, 9],
        "header": 1,
        "map": {"1": "pitch3", "2": "gate3", "3": "pitch4", "4": "gate4",
                "5": "run", "6": "reset", "7": "roll", "8": "feedback"}
      }]
    }
  ]
}
```

```sh
hydrapy studio patches/gorgon_corridor.py --tracker --cv-profile my-cv.json
```

Use the actual patch path for your workspace. If both S/PDIF pairs are on one
interface, put both units in that device's `es40` list with distinct channel
pairs; HydraPy opens one audio stream per device. Optional `"direct": "0=clock,1=reset"`
on a device adds direct DC outputs on other channels in that same stream. Profiles
reject overlapping routes. Two devices share the musical playhead, but independent
hardware clocks and output latencies still require workstation measurement. Set
`--cv-offset-ms` after measuring; a common offset does not correct different
per-device latencies. Use 44.1 or 48 kHz, matching the audio device and digital
clock. High-rate SMUX is not implemented.

Unused ESX-8CV jacks are explicitly sent zero volts. Pitch uses the same notes
and key transposition as the browser's FM/Sub voices, default C4 = 0 V and 1 V/oct.
`--cv-pitch-zero` changes the MIDI note at 0 V. Outputs clip at the expander's
12-bit range. Use the factory-calibrated range: the expanded-range jumper changes
the voltage scale and is not handled by this encoder.

## Establish the digital path before using a score

1. Check the ES-40's input-lock LED. No lock points to the S/PDIF route, cable or
   clock before note generation. Use its S/PDIF input; its output is for ES-7
   expansion, not a pass-through connection for a second ES-40.
2. Confirm which of the five ES-40 expansion headers holds each ESX-8CV. If
   changing ribbon connections, power the rack down first; follow the manufacturer's
   orientation instructions. Configure that header in the profile/VCV encoder.
3. Generate an independent 18-second diagnostic:

   ```sh
   hydrapy es40-check --header 1 --samplerate 48000 -o es40-header1.wav
   ```

   Route this **data WAV only to the ES-40's S/PDIF pair**, at unity, with no
   fades, pan law, normalization, effects, sample-rate conversion, dither, or other
   audio mixed into that pair. It is not listening audio. Match the file and device
   rates. A meter should show zero first, then 1 V on jacks 1–8 individually for
   one second each, with one-second zero intervals, ending at zero. A recording
   of the digital path can be compared against the original PCM to find bit changes.
4. Once that works, launch Studio and test one `pitch`/`gate` pair, then both units.
   Check 0 V / 1 V pitch intervals and sustained clock stability. Normal shutdown
   clears outputs, but a crash or unplugged cable may leave the expander holding
   its last voltage; do not treat loss of digital audio as a zero-CV command.

For VCV, the documented chain is **CV sources → 8CV Encoder → matching input
1–5 of ES-4(0) Encoder → Audio module's S/PDIF L/R pair**. The ES-4(0) Encoder
also has Category A/B/C in its context menu, affecting float-to-PCM scaling.
Confirm the interface's required category and keep the complete digital path
bit-preserving. These are troubleshooting checks, not a diagnosis of why either
unit failed on this workstation. The diagnostic WAV bypasses VCV's encoder and
helps separate patch configuration from the downstream digital path.

Manufacturer references: [ES-40 manual](https://www.expert-sleepers.co.uk/es40usermanual.html),
[ESX-8CV manual](https://www.expert-sleepers.co.uk/esx8cvusermanual.html),
[VCV encoder connections](https://www.expert-sleepers.co.uk/vcvrack_encoders.html).

## Reproduce the software checks

```sh
python -m pytest -q tests/test_es40.py tests/test_tracker_cv.py tests/test_studio_tracker.py
HYDRAPY_BROWSER_TESTS=1 python -m pytest -q tests/test_studio_tracker_browser.py
PYTHONPATH=. python tools/benchmark_tracker_cv.py
```

Protocol tests compare all five headers against a fixture generated by the pinned
manufacturer C++ source, then independently decode voltage words, clipping, packet
boundaries, two-unit isolation and diagnostic output. Fake-device tests check
configuration failures, integer output and cleanup. The fixture generator is in
`tests/fixtures/make_es40_reference.py` and requires a compiler and an upstream
checkout at the pinned commit.

A container run with Python 3.13.16 and 2,000 measured 256-frame blocks gave
0.63 ms median / 0.83 ms p95 / 0.97 ms p99, versus 5.33 ms per block at 48 kHz,
for dense four-voice patterns, full automation and two encoded units, while the
regression suite was also running. This measures
callback computation without audio hardware, not a real-time scheduling guarantee.
The physical Ubuntu interfaces, S/PDIF bits, expanders, tuning, inter-device drift
and A/V latency remain unvalidated.
